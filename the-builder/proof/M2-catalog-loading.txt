main.rs no longer contains ../ah.ttl or ../not-ah.ttl. It reads exactly one
file path literal: "catalog-v001.xml" (the bare filename, no directory
traversal) -- the same unavoidable bootstrap convention ah-workbench's own
lint.py uses (CATALOG_FILE = "catalog-v001.xml", run from the folder that
holds it). Confirmed by grep: no other path-shaped literal remains.

What changed:
- parse_catalog(): not a general XML parser, just enough for
  catalog-v001.xml's own fixed shape (flat <uri name="..." uri="..."/>
  elements) -- adding a real XML crate wasn't asked for and the format is
  ours to keep simple.
- load_via_catalog(seed): walks owl:imports transitively from the seed,
  resolving every encountered name through the catalog. A name the catalog
  doesn't map calls eprintln!+exit(1), same style as the existing cycle
  check -- not a silent skip.
- load_file() tries Turtle first, falls back to RDF/XML on failure, since
  M1's vendored copies are a mix of both and the catalog doesn't currently
  record which is which.
- Single seed: https://drift-king.org/ah.ttl. Its own owl:imports already
  lists not-ah.ttl, so one seed reaches both -- no second hard-coded load.
- ah/the-builder/build's command changed to
  "cargo run --release --manifest-path the-builder/Cargo.toml", run from
  drift-king root, not "cd the-builder && cargo run --release". Verified
  first (throwaway crate): --manifest-path builds and runs the binary
  without changing the caller's cwd, so catalog-v001.xml's relative paths
  (relative to the repo root, same as the catalog itself) resolve
  correctly. Model changed before the code that depends on it.
